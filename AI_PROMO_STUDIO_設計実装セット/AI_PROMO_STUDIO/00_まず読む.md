# AI PROMO STUDIO｜設計・初回実装セット

**構想**：自然文でAIに動画構成を依頼 → ブラウザの編集画面で1コマずつ微調整 → 難しい変更だけAIに部分依頼 → **確定後にMP4/共有HTMLとして出力**。

これは**実装前の要件定義・UI/UX仕様・JSON設計・Codex依頼文**と、編集の手触りを確認するための**単体HTML操作モック**をまとめたものです。完成した動画制作アプリではありません。

## 最初に試すこと

1. `prototype/AI_PROMO_STUDIO_UIモック.html` をChrome等で開く。
2. 下のタイムラインで3コマ目を選択。
3. 秒数を7秒→9秒にする。合計22秒になる。
4. レイアウトを4分割→自由、文字やモーション、スキャンON/OFF、色を編集。
5. 「JSON出力」「部分編集依頼をコピー」を試す。

**注意**：このHTMLは**UI操作モック**であり、Remotion接続・MP4出力・正式project.jsonとの完全互換・AI自動呼び出し・素材の永続保存は未実装。素材の読み込みは一時プレビュー。出力されるJSONは**モック形式**なので、そのまま実装時のproject.schema.jsonの正本として扱わないこと。

## Cursor / Codexに渡す順序

1. **新しい独立リポジトリ／空フォルダ**を作る。
2. このセットを展開して設計資料と参照データを作業フォルダに置く。
3. `04_Codex実装依頼文.md` を読ませる。残りの3文書とサンプル・60カタログも**先に確認してから**実装するよう指示する。
4. 最初は **Step 1/2＝共通動画JSON→ブラウザプレビュー→コマごとの編集**を完成させる。
5. 次にRemotionモーション4〜6件、AI patch差分承認、最終MP4/HTMLの順。

## なぜこの順番なのか

最初から全60件の動画化や完全自動AI連携を作ると、UI変更のたびに既存動作が壊れるリスクが増えます。重要なのは**完成した編集状態を毎回確実に再現し、MP4へ一度で出力できる設計**。

MOTION ATLAS 60の現状はCanvasの試作品。全モーションがRemotionで動くわけではありません。IDを流用し、**必要なものから再実装して検証する**方針です。

## 想定する実装基盤

- ローカル開発：Windows + Node.js / Cursor + Codex
- UI：Vite + React + TypeScript
- 動画：Remotion Player（プレビュー） + Remotion Renderer（MP4）
- 保存：ローカルJSON + フォルダ内素材（MVPはDB不要）
- AI：まずCursor/CodexがJSON・patch候補を作成（Web側のAI API自動実行は後続）
- セキュリティ：localhost限定、既存プロダクトの本番操作なし、外部素材ライセンス確認
