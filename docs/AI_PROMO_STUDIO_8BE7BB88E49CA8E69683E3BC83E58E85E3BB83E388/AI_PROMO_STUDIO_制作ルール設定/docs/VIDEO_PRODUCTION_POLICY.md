# AI PROMO STUDIO｜動画制作標準ルール v1.0

> 対象：新規プロモーション動画の制作依頼、既存動画の全面再企画。通常の部分修正には必要な工程だけ再実行する。
> 目的：単なるスクリーンショット・文字・モーションのはめ込みを避け、実証された製品価値を、伝わる映像企画に変換する。

## 0. 絶対原則

1. **考えてから作る。** 対象の調査と企画が終わる前に本制作・MP4出力しない。
2. **実証済みの機能だけを事実として表現する。** 観察／推測／未確認／演出上の仮表現を分ける。
3. **素材を載せるだけの動画を合格にしない。** 全シーンに「伝えたい価値」と「なぜその撮り方か」を持たせる。
4. **モーションは意味を持って使う。** 新しい動きを無条件に増やさず、視線誘導・理解促進・感情表現に資するものを選ぶ。
5. **映像企画と実装を分離する。** 複数の表現案と絵コンテを先に作成。承認した案を実装する。
6. **ユーザーによる手動編集を保持する。** AI再生成時に確定済みシーン・色・画像・時間配分を勝手に上書きしない。
7. **参考動画は分析し、模倣・無断転載しない。** 著作権・利用規約を確認する。実写・音声・画像素材も同様。
8. **記録を残す。** 根拠、採否、修正履歴、未確認項目を保存する。

## 1. 新規依頼を受けたら必ず実行する5段階

### Phase 1｜徹底した製品・デモ調査

- URL、ローカルアプリ、画面、リポジトリ、説明資料等を収集する。アクセス不能ならその制約を明示する。
- 誰が、どんな状況で、なぜ使うかを整理する。
- 主要画面、操作フロー、入力、ボタン、前後の状態、処理結果、導線を実機で確認する。必要ならPlaywrightで証拠となるキャプチャ、操作ログ、トレースを取得する。
- 実際に使える機能・未実装の機能・動作未確認の機能を区別する。
- 撮影・ログイン・外部送信を伴う検証はテスト環境／テストデータを優先。本番のデータ変更・送信・決済等は承認なしに行わない。
- 最も特徴的な操作と、映像で見せた場合に魅力が伝わる変化を抽出する。

**必須成果物**：`research/product_audit.md`、`research/evidence.json`、画面キャプチャ等の参照情報。

調査結果に以下を含める：
- 強み・ユースケースの一覧と根拠
- おすすめの撮影箇所（画面・対象要素・操作手順・操作前後の状態）
- 事実として伝えられる内容と、まだ確認が必要な内容
- ターゲット別に伝わりそうな魅力の仮説

**ゲート G1**：一次資料または実機操作による根拠が揃った主訴求だけを企画の事実として採用する。足りない場合は「要確認」と記載して進めるが、確定的な効能・数値を広告に使わない。

### Phase 2｜訴求戦略と企画案の作成

- 目的：認知、理解、利用促進、問い合わせ、イベント告知などを特定。
- 視聴対象、視聴環境（SNS縦型・Web埋込・会場ディスプレイ等）、尺、トーンを整理。
- **この動画で視聴者に一つだけ覚えてほしいこと**を1文にまとめる。
- 「機能」→「ユーザー体験の変化」→「価値」を整理し、数字を使うなら根拠を添える。
- 参考CMから、カット割り・視線誘導・間・文字の出し方・音の効果を構造として抽出する。参考動画にない演出を「分析済み」と断定しない。
- 標準で**異なる発想の3案**を出す（単なる色違いは禁止）。例：操作実演型／価値訴求型／印象重視型。ただし最適な3軸は対象製品から選ぶ。
- 各案に狙い、冒頭のフック、主役となる操作、見せる価値、構成、メリット・弱点、制作負荷を付ける。

**必須成果物**：`planning/creative_brief.md`、`planning/concepts.yaml`。

**ゲート G2**：ユーザーが選択・修正するまでは「企画案」扱い。承認が不要な自動デモモードでも、仮採用であることを明示し、MP4の最終確定とは区別する。

### Phase 3｜絵コンテと映像演出の詳細設計

- 選んだ企画を秒数に分ける。20秒など既存の定型配分を無条件に適用しない。
- **各ショット**に下記を設計する：
  - 開始・終了時刻、画面の目的、視聴者に伝える要点
  - 画面構成（1面・2分割・4分割・自由レイヤーなど）
  - 対象素材とその根拠ID、使用する実際の画面や操作
  - カメラ（寄り・引き・追跡・切替）、フォーカス位置と変化
  - 操作（例：ボタンへズーム→クリック→処理結果の比較→成果を訴求）
  - テキスト原稿（短く、読み切れる量）、読みやすい背景・文字色
  - 音／SE／無音の意味、入るタイミング
  - モーション候補、その演出を使う**理由**
  - 何を表現するか（説明・驚き・信頼・ワクワクなど）
- **商品の理解**と**印象的な表現**の両立を確認する。「画像が動くだけ」のショットは差し戻す。
- 動きの効果が強くても、画面のボタン名・操作・処理結果が見えなければ再設計する。

**必須成果物**：`planning/storyboard.yaml`、`planning/director_notes.md`。

**ゲート G3**：絵コンテをユーザーに表示し、シーンごとの変更・コメント・承認に対応。確定部分はロックまたは差分承認対象とする。

### Phase 4｜モーションの選定と仮制作

- MOTION ATLASから必要なモーションを用途・感情・速度・対象レイヤーの互換性で絞り込む。
- 既存モーションで足りない場合だけ新規アニメーションを設計する。
- 製品の実際の画面／録画／画像を優先し、その上でフォーカス、カメラ、トランジション、タイプライター、スキャン等を重ねる。
- 静止スライドの連続ではなく、時間軸上で操作や見せ場が連続するように組み立てる。
- ブラウザの仮プレビューを作り、シーンごとの秒数・配色・構図・素材・動きを調整可能にする。

**必須成果物**：編集可能なプロジェクトJSON、プレビュー、要素別モーション情報。

**ゲート G4**：プレビューのレビューと修正を経て、ユーザーが最終出力を指定するまで高品質なMP4本番レンダリングを実行しない。

### Phase 5｜レビューと最終書き出し

品質チェック：
- 冒頭数秒で見る理由が分かるか
- 製品固有の魅力と実際の画面が伝わるか
- 「操作→変化→価値」のつながりが理解できるか
- 文字が多すぎず、画面の視線誘導は明確か
- 動きは必要か、単なる賑やかしになっていないか
- 参照根拠と実物の操作に矛盾がないか
- BGMと効果音が視聴を邪魔しないか、音なしでも最低限伝わるか
- プレビューと出力の内容が一致しているか
- 権利と広告表現に問題がないか

**必須成果物**：`review/quality_report.md`、最終プロジェクトJSON、指定形式の成果物。

## 2. 動画の内容が「単なるはめ込み」に戻らないための失敗判定

次に該当したら企画／演出を再検討する：
- 全シーンが「スクショ＋タイトル＋フェード」になっている。
- 製品の機能を実際に動かして確かめていないのに、機能の効果を説明している。
- カメラ、フォーカス、切替、演出が機能の説明や感情の誘導に結びついていない。
- 商品の固有性が消え、別の商品名に差し替えても成立してしまう。
- 参考CMを挙げるだけで、そのどの表現原理を採用したか説明できない。

## 3. ブラウザ画面への追加

制作管理に **「調査」「企画」「絵コンテ」「編集」「レビュー／出力」** タブを置く。
- 各工程には、成果物リンク、状態（未着手・作業中・要確認・承認済み）、不明点、次の操作を表示する。
- 企画はカードで比較し、案ごとのメリット／懸念点と採用理由を表示する。
- 絵コンテは画像・操作・テキスト・秒数・モーションIDをシーン単位で編集可能にする。
- 編集画面には、`ショットの目的` と `表現する製品価値` を短く表示し、単なる配置変更にならないようにする。
- ユーザーの手動編集・確定状態・未実装の自然言語メモを保持して差分のみAI修正する。

## 4. ワークフロー実装ルール

プロジェクトには段階と承認履歴を永続化：

`intake → audited → concept_proposed → concept_approved → storyboard_proposed → storyboard_approved → preview_ready → export_approved → exported`

単に見た目の「次へ」ボタンを作るだけでなく、サービス側の遷移処理とレンダー実行側で状態を検証する。
- 未承認の企画は初稿プレビューまで。最終公開や確定レンダリングは承認後。
- 部分修正では変更対象に必要な工程だけ無効化。例えば文字色の修正で製品調査からやり直さない。
- デモの機能や事実に影響する変更の場合、関連根拠と構成から再確認する。
- 確定した企画を変更する場合は、新版を作り旧版を保持。ユーザーの変更を黙って上書きしない。

## 5. 作品の目的に応じて変えるもの

調査・企画・レビューを省略しない一方、**映像の形式を固定しない**。
- 操作説明中心：実際のボタンや処理結果が主役。ズーム・マスク・手元やカーソルの演出を優先。
- ブランドCM中心：情報量を絞り、製品の特徴を象徴する操作と感情の流れを優先。
- トーナメント告知：会場の高揚感、対戦、人物、音のシンクロを優先。ただし既存イベント情報の確認を行う。

既存の画面構成・色・素材・モーション・書き出しを維持したまま追加する。
