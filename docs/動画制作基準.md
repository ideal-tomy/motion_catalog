# motion_catalog 動画制作基準

この文書は、このワークスペースで動画を新規制作・修正するときの唯一の詳細基準です。通常の制作では `AGENTS.md` と本書を読み、案件固有の依頼・素材・編集データを確認します。アプリ開発資料や60種すべてのモーション説明を毎回読み込まず、必要なときだけ該当資料・選択したモーションIDを参照します。

## 基本原則

- 素材・スクリーンショットを並べて動かすだけで終えず、対象固有の価値と、各ショットの目的を設計する。
- 実際に確認した事実、推測、未確認事項、演出用の再構築を区別する。未確認の機能・実績・数値を広告で断定しない。対象アプリは原則読み取り専用とし、個人情報・認証情報を撮影しない。
- 実画面や実操作の変化を優先し、「操作→画面上の変化→視聴者に伝わる価値」をつなげる。参考CMは構成・視線誘導・間・音の原理を学び、素材や演出を複製しない。
- モーションと切替は視線誘導・理解・感情に役立つ理由を持たせる。依頼に「重複なし」などの条件があれば全編で照合する。演出の形式・尺・画面構成は案件の目的に合わせ、固定テンプレートにしない。
- 手動で確定した編集、素材、配色、尺、未変更ショットを保護する。変更は対象を絞り、差分を把握してから適用する。

## 新規制作・全面再企画

1. **実査**：対象の用途・視聴者、主要画面、実操作、前後の変化、価値を調べる。根拠と未確認事項を記録し、アクセス不能な箇所は推測で埋めない。
2. **企画**：用途・尺・画角・トーンと、視聴者に残す主メッセージを決める。依頼の自由度が高い場合は、操作実演・ブランド印象・課題から変化など異なる方向性を比較する。具体的な演出指定がある場合はその意図を優先し、不要な案出しを増やさない。
3. **絵コンテ**：各ショットに時間、目的、実画面・根拠、実演内容、構図・フォーカス、コピー、音、モーションと採用理由を定める。説明の詰め込みや、別製品にも置き換えられる一般的な映像になっていないか確認する。
4. **承認・仮制作**：企画と絵コンテをユーザーが確認できる形にする。承認された構成を編集可能な案件データと仮プレビューへ反映する。最終MP4の確定書き出しは、プレビュー内容を確認した明示的な承認後に行う。
5. **QA・納品**：実画面との一致、主メッセージ、文字の可読性、音量・音切れ、尺・画角、黒画面、プレビューとMP4の一致、権利を確認する。未確認・未完了は隠さず記録する。

## 既存動画の修正

| 変更 | 再確認する範囲 |
|---|---|
| 誤字・色・位置など単一レイヤーの修正 | 対象レイヤーと共通プレビュー、該当するQA |
| ショットの素材・尺・構図・動きの変更 | そのショットの根拠・演出、前後とのつながり、プレビュー、QA |
| 製品機能・主訴求の変更 | 関連する実査根拠、企画、該当ショット、プレビュー、QA |
| 全体の方向転換 | 新規制作と同じ実査・企画・絵コンテの工程 |

既存案件を先に特定し、修正対象と維持する内容を分けます。無関係なショットを再生成せず、確定済みの内容を黙って上書きしません。修正版は新しい版として保存し、旧版・編集元・原素材を保持します。

## 画面・レイヤーの見せ方

- 角丸カードやブラウザ枠を既定にしない。素材の目的に応じて、枠なし全画面、拡大・再構図、切り抜き、レイヤー合成、意図のあるフレームを選ぶ。
- 元画面を単に枠へはめず、視聴者が見るべき操作・変化を大きく見せる。実画面と演出用再構築は誤認されないよう区別する。
- 編集可能な素材・文字・背景・装飾は別レイヤーで保ち、全体配色と素材内に焼き込まれた色を区別する。選択線やハンドルなど編集UIは動画に出さない。
- 設定値だけで完了とせず、共通プレビューで実際の表示・動きを確認する。

## 保存と版管理

- 制作データ・根拠・編集元は `promo-studio/jobs/<job>/` に保持する。完成品は `動画ライブラリ/` に「1作品1フォルダ」で集約し、一覧から探せる状態にする。
- フォルダとMP4・HTMLの基本名は `動画フォルダ_<対象>_<雰囲気><実尺>秒_<言語>_<画角>_<内容>_<YYYYMMDD>_vNN`。尺は実測値、画角は出力解像度に合わせる。
- 各案件に `delivery.json` を用意し、レンダー→QA合格→ライブラリ集約の順に行う。実装済みの `render.mjs`・`qa.cjs`・`npm run library` を使う。
- 同じ版名の別内容で上書きしない。修正時は版番号を上げる。jobs、既存の完成版、共有HTML内の必要なメディア複製を自動削除・移動しない。

## 参照範囲を絞る

- **通常の制作**：`AGENTS.md`、本書、今回の依頼、対象案件だけ。
- **UIや制作システムの改修**：上記に加え、変更対象の要件・現状・実装仕様だけ。`docs/ディレクター.md` などの実装依頼資料は動画の企画基準として扱わない。
- **スタイル検討**：案件で指定された参考資料のみ。`理想.md` は現在UI/UX改善の指示書なので、動画の演出希望として自動適用しない。
- **モーション選定**：候補を絞ってから該当IDの説明を読む。未移植の参照モーションを実装済みとして扱わない。

導入用のサンプル一式は `docs/AI_PROMO_STUDIO_8BE7BB88E49CA8E69683E3BC83E58E85E3BB83E388/` に保管されています。そこにあるYAMLはアプリ実装の例であり、AIが動画制作時に読む正本でも、アプリに実装済みの承認制御でもありません。
