# AI PROMO STUDIO｜全UI調査にもとづく「操作を探せるHTMLガイド」制作依頼

## 0. 今回の依頼で実現したいこと

AI PROMO STUDIOの機能が増え、操作の意味や場所が分からなくなっている。特に設定項目がアコーディオンの中に収まり、タブ切り替え・選択対象・編集モードによって表示項目が変わるため、目的の操作に到達しづらい。

**まず既存アプリの実際のソースコードとブラウザ表示を徹底的に調査し、操作項目の意味、操作場所、現れる条件、使い方を日本語で説明する、検索可能なHTMLガイドを制作・実装してほしい。**

今回はUI機能の全面改修を主目的としない。最初に「実際に使える操作ガイド」を完成させる。日本語の名称・導線の改善案は別途まとめ、承認なしで名称や配置を大量変更しない。

既存画面右上に「操作ガイド」ボタンがあるため、**まずその実装と遷移先を調べ、重複したガイドを作らず既存導線と統合する**。

## 1. 作業順序（必須）

### Phase A：現状のUI/操作導線を全件調査
1. プロジェクト内の画面・ルーティング・コンポーネント・タブ・アコーディオン・ボタン・入力・ショートカット・ツールチップ・関連する状態管理を調査する。
2. ローカルアプリをブラウザで起動し、通常の操作によって**実際にどの表示になるか**を確認する。DOMテキストやソースコードだけで「使える」と断定しない。
3. 選択対象によって項目が変わる場合、以下を別々に確認する。
   - 未選択／シーン全体／レイヤー／テキスト／画像・動画／フレーム・図形／複数選択（対応していれば）
   - 編集モード／再生モード
   - 左側「構成」「素材」「動き」「AI部分修正」「修正メモ・引き継ぎ」等の各タブ（実装を確認した項目のみ採用）
   - 右側の「コマ」「レイヤー」「全体」、各アコーディオン
   - タイムライン、ライブプレビュー、保存・JSON出力、再生、アニメーション適用
4. 各操作項目について最低限以下の記録を残す：
   - **表示名（画面に出る文言そのまま）**、内部機能名、ユーザー視点のわかりやすい別名
   - **意味・できること・できないこと**
   - **到達経路**（例：ライブプレビューでテキストを選択 → 右「レイヤー」 → 「文字」 → 「文字揃え」；実在を確認して記載）
   - **表示条件**（どの対象を選択すると現れるか）
   - **操作手順**（3〜6ステップ程度、操作結果）
   - 設定値の保存範囲（選択レイヤー／現在のシーン／動画全体）と戻し方
   - UI実装ファイル、該当コンポーネント、実ブラウザ検証結果
   - 機能状態：利用可能／一部実装／未接続／不明（実装と表示を突き合わせる）
5. 結果を `docs/ui-guide/UI_AUDIT.md` に保存し、未確認箇所は明記する。

### Phase B：ユーザーが探しやすい情報設計
HTMLガイドは、少なくとも下記3つの探し方を持たせる。

**A. やりたいことから探す（最優先）**
- テキストを書き換える
- テキストを中央揃えにする（**枠の中の文字位置**）
- テキストボックス自体を画面中央に置く（**オブジェクトの座標**）
- テキストのサイズ・色・改行・行間を調整する
- ドラッグで画像や文字の位置を調整する
- 画像のサイズ変更・切り抜き・フレームへのはめ込み
- 選択中の画像だけを動かす／フレームごと動かす
- アニメーションを追加・時間調整・削除する
- シーン（コマ）の秒数を変更する／シーンを複製する
- 全体色を変える／シーンだけ変える／レイヤーだけ変える
- 保存する／元に戻す／JSONを出力する
- AIへの修正依頼メモを残す／引き継ぎ資料を出力する
※実際に未実装の項目は「未対応／開発中」として区別し、あるように説明しない。

**B. 画面の場所から探す**
- ヘッダー
- 左パネル（各タブと配下）
- 中央のライブプレビュー（編集モード・再生モード）
- 右パネル（選択対象に応じた編集項目）
- 下部タイムライン
- モーション図鑑、素材一覧、レイヤー編集、確認事項
画面写真または簡単な図で領域を示し、領域をクリックすると詳細へ移動できるようにする。

**C. 言葉・用語から探す**
例：
- 「コマ」＝動画の一つの時間区間。ガイドでは原則 **「シーン（コマ）」** と併記
- 「レイヤー」＝シーンに重ねる文字・画像・動画・図形などの編集対象
- 「フレーム」＝画像などを収める枠／表示領域（アプリでの実際の定義を優先）
- 「文字揃え」と「ボックス配置」の違い
- 「移動」「整列」「スナップ」「トリミング」「適用範囲」「尺」「緩急」など
必ず実装に基づいて定義を確定する。

### Phase C：HTMLガイドを実装
1. **Markdownの長文をそのまま1ページに並べたものにはしない。** 情報探索に特化した読みやすいHTMLガイドを実装する。
2. 既存アプリと同じ技術スタック・ルート構成を調査し、最も保守しやすい方法で追加する。適切な既存ページがあれば拡張する。
3. ホームは「何をしたいですか？」の大きな検索欄＋よくある操作カード＋画面マップ＋用語集への入口。
4. キーワード検索は表示名だけでなく、俗称・同義語・ひらがな（例：「中央揃え」「真ん中」「文字の位置」「テキスト変更」「ドラッグ」）にも対応。検索結果に **操作名・意味・場所・条件** を表示する。
5. 各操作の詳細ページ（または詳細パネル）を共通テンプレート化する：
   - 何ができるか（まず1〜2行）
   - **どこにあるか**（パンくず／タブ／選択対象／アコーディオン名）
   - **操作前の条件**（例：テキストレイヤーをクリック）
   - **スクリーンショットまたは短い操作アニメーション**（実際のブラウザから取得。必要なら静止画から開始）
   - 手順（番号付き）
   - 変更結果の見え方・適用範囲
   - うまくいかない場合（表示されない、選択対象が違う、再生モードなど）
   - 関連する操作へのリンク
   - 実装状況・最終確認日
6. 各見出しは折りたたみ可能にしてよいが、**深すぎるネストは禁止**（目安2階層）。開閉式だけに依存せず、検索や目次から直接辿れるようにする。
7. 可能なら現在のアプリから該当設定画面を開く「この設定へ移動」リンクを追加。ただし実装済みの遷移・選択状態に対してのみ。難しければ明確な手動の到達経路を掲載し、動かないボタンは設置しない。
8. PC幅・モバイル幅で検索欄、カード、本文を検証。フォントは日本語の可読性を優先し、小さすぎる文字を避ける。キーボード操作とフォーカス表示にも配慮。
9. スクリーンショットは実UIに即したものを使い、機密情報や顧客データが写らないようにする。撮影時はサンプルプロジェクト・ダミー素材を使用する。
10. 表示の見栄えだけでなく、ユーザーが**目的の機能へ迷わず到達できる**ことを重視する。

### Phase D：分かりにくい名称と導線を別途提案
監査に基づき、次のようなUI改善候補を `docs/ui-guide/UI_LABEL_AND_NAVIGATION_PROPOSALS.md` にまとめる。
- 「コマ」だけで意味が伝わらないなら「シーン（コマ）」にする等の改善案
- 「左右中央揃え」が「文字揃え」なのか「ボックスの配置」なのか分からない場合、役割を明確にする案
- 選択した種類で設定ボタンが突然消える／タブを移ると現在地が分からない問題
- 選択中の対象名・編集対象の階層（全体 > シーン > レイヤー）を常時見せる案
- よく使う編集へのショートカットや、設定項目の検索
- 表示条件・名称・階層が不一致な箇所

**この段階では提案を作ることが主で、アプリの既存ラベルや操作UIを無断で大規模変更しない。** ガイドの動作に最低限必要な改修は理由と影響を明記する。

## 2. ガイドの画面構成（提案）

```
┌────────────────────────────────────────────────────────────────────┐
│ AI PROMO STUDIO 操作ガイド                 [ 機能・操作を検索... ] │
├────────────────────────────────────────────────────────────────────┤
│ よく使う操作                                                        │
│ [文字を編集] [文字を中央揃え] [画像を動かす] [秒数変更] [保存]      │
├────────────────────────────────────────────────────────────────────┤
│ 画面のどこ？                                                        │
│ [ヘッダー]  [左：素材/構成/動き]  [中央：プレビュー] [右：設定] ...│
├────────────────────────────────────────────────────────────────────┤
│ 用語が分からない？                                                  │
│ シーン（コマ）／レイヤー／フレーム／適用範囲／スナップ              │
├────────────────────────────────────────────────────────────────────┤
│ 検索結果：「テキスト 中央」                                          │
│ ① 枠内の文字を中央揃え     場所：レイヤー > 文字 > 配置             │
│ ② テキストボックスを中央へ 場所：レイヤー > 位置・サイズ            │
│ ※ 上記の正確な経路は現行実装を監査してから記入する                  │
└────────────────────────────────────────────────────────────────────┘
```

## 3. 最重要の混同防止（必ず個別に実機確認）

**例1：「テキストを中央揃え」**
- A：テキストボックス**内**の文字列の揃え（text-align）
- B：テキストボックス**自体**の左右・上下中央配置（position）
- C：複数レイヤー間の整列
これらが別の機能なのか、いずれか未対応なのかを調べ、それぞれ別のガイド項目で説明する。

**例2：「ドラッグする」**
- A：要素の位置を動かす
- B：選択枠を伸ばしてサイズ変更する
- C：素材をキャンバスへ配置する
- D：タイムラインの開始／長さを変更する
それぞれ、編集モード・選択状態・スナップ・比率固定などの条件を実際に確認する。

**例3：「動きを付ける」**
- シーン全体／フレーム全体／枠内画像／テキストレイヤーで適用対象が違う
- 「実装済みでプレビュー可」と「MP4出力まで対応」の違いを正確に記載する

## 4. データ管理と保守
- ガイドの1項目を `id`, `title`, `aliases`, `summary`, `category`, `locationPath`, `selectionPrerequisites`, `steps`, `scope`, `screenshots`, `status`, `relatedIds`, `sourceFiles`, `verifiedAt` 等で管理できる形を推奨。
- 機能追加時、該当ガイド項目も更新できる構成とし、追加漏れを検出できるチェックリストを用意。
- ガイド全文と検索インデックスはローカルで動くようにし、閲覧のたびにAI APIやネット接続を要求しない。
- 保守のためのMarkdown監査レポートは残すが、**利用者が日常的に読む一次資料はHTML**とする。
- 出典なしの推測や機能の水増しは禁止。条件付き表示・未実装部分は正直に明記。

## 5. 受け入れテスト（必須）
1. 右上「操作ガイド」から一回の操作でガイドに入れる（既存導線を流用）。
2. 「文字を真ん中に」と検索すると、**枠内文字の中央揃え**と**ボックス自体の中央配置**が別々に見つかり、差が分かる。
3. 「テキストを書き換える」と検索して、対象を選択するところから正しい到達経路が表示される。
4. 「画像をドラッグ」と検索して、画像選択と移動の操作条件が分かる。
5. 「コマ」と検索して、シーンの意味と時間範囲の編集場所が分かる。
6. どれかひとつの説明に従って実ブラウザで操作し、ユーザーが目的を達成できることを確認する。
7. アコーディオンを閉じた場合やタブを切り替えた場合の導線も確認する。
8. ガイドに記載した機能の未実装・条件付き動作が正確に表記される。
9. PCとスマホで検索・一覧・詳細ページを使える。
10. 既存プロジェクトの編集・保存・再生・Undo/Redo・JSON出力に回帰不具合がない。

- **実際にブラウザで利用できるHTML操作ガイド**：既存アプリ内のページまたは適切な静的配信ルート
- `docs/ui-guide/UI_AUDIT.md`：現在の機能一覧と表示条件の監査
- `docs/ui-guide/UI_LABEL_AND_NAVIGATION_PROPOSALS.md`：分かりにくい名称と改善案
- `docs/ui-guide/GUIDE_CONTENT_STRUCTURE.md`：ガイドの分類・用語・運用方針
- 実際の操作説明に必要なサンプル画面画像（安全なダミーデータ）
- 実施したテストの結果、未確認事項、今後の更新手順

## 7. 作業時の禁止事項
- ソースコード未確認のまま、UIや機能の存在を推測して説明しない。
- **Markdownレポートだけで完了扱いにしない。HTMLをブラウザで開いて検証すること。**
- 既存の「操作ガイド」導線を無視して似たページを重複作成しない。
- 依頼していない全面UI改造、コマ・レイヤーの再設計、プロジェクトデータ移行を行わない。
- 既存データ、手動編集内容、保存済みプロジェクトを破壊しない。
- わからない機能を「利用できます」と断言しない。
