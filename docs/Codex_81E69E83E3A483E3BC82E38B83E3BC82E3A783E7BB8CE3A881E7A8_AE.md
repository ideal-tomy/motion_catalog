# AI PROMO STUDIO｜選択レイヤー用アニメーション登録・適用機能 実装依頼

## 目的
既存のローカル AI PROMO STUDIO v3 に、**「選択したレイヤーに対して、アニメーションをその場で試し、設定を変更し、採用・保存できる」**機能を追加する。

ユーザーの期待する操作例：
1. コマを選択し、画像が入った円形フレームをクリックする。
2. 「動き」から「左へ退出」を選ぶ。
3. 「フレーム全体を動かす／枠を固定して内部画像だけ動かす」を選ぶ。
4. 中央プレビューで右から左へ動いて画面外へ消える様子を再生・シークして確認する。
5. 開始 1.2 秒、長さ 0.8 秒、イージング ease-in、退出先はコマの画面外、という数値を変更して確認する。
6. 「試着→採用」すると設定がプロジェクトに保存され、Undo/Redo、JSON 書き出し、MP4 に引き継がれる。

**最優先事項**：既存のシーン、レイヤーの配置・サイズ・色・素材・画像トリミングを壊さない。既に開発中の色・フレーム変更反映の修正を上書き・後退させない。

## 実装順序：必ず ①登録 → ②適用 の2段階

### Phase 0｜着手前の現状調査（変更なし）
- 既存のリポジトリ、React / Remotion構成、シーン・レイヤー・フレームのデータ構造、選択中レイヤー ID の取得方法、タイムライン・プレビューのレンダラー、保存・Undo/Redo、素材管理の実装を調査する。
- 既存 MOTION ATLAS 60 の ID・サムネイル・プレビューを利用できるか確認する。別のアニメーションエンジンを無断で追加しない。
- 「コマ全体の動き」と「選択レイヤー個別の動き」が混同されないよう適用先の構造を整理する。
- 調査結果と最小変更方針を `docs/animation-extension-audit.md` に記録する。

### Phase 1｜代表的アニメーションのカタログを先に定義・登録
まず**以下24件を実装対象とする**。それぞれ安定した ID、表示名、説明、カテゴリ、適用可能な対象、デフォルト値、調整項目、プレビュー可能／適用可能／MP4 出力対応のステータスを持たせる。名称のみのダミー登録は禁止。

カタログの各項目には以下を登録する：
- `id`, `name`, `category`, `description`, `tags`, `supportedTargets`, `parameters`, `defaultParams`, `previewSample`, `status`。
- `tags`：印象（迫力・信頼・高級・癒しなど）、速度感、登場／退出／継続／強調、方向、素材種別。
- `supportedTargets`：scene / group / frame / imageContent / text / shape。非対応は選択不可とし理由を表示する。
- 同じ動作でも `frame` と `imageContent` では結果が異なるため、`targetScope` を明示する。
- 現在の「M-001〜M-060」は**参照用のIDとして維持**し、今回の A-001〜A-024 は「実際に適用するプリセット ID」として別管理する。将来、M→A の対応表を作れるようにする。既存 ID を勝手に変更しない。
- カタログを YAML / JSON / TypeScript のいずれかの単一ソースで定義する。表示一覧と実動作の定義を別々に手書きして乖離させない。

**Phase 1 の成果物**：カタログデータ、動く小プレビュー（最低でも各項目の再生確認）、分類と検索／フィルタ。まだ「適用できない」段階なら明示する。カタログ完成後、Phase 2 に進む。

### Phase 2｜選択レイヤーに適用・リアルタイムプレビュー
#### 操作フロー
1. 中央プレビューか右側のレイヤー一覧で、対象を1つ選択する。
2. 「動きを追加」からカテゴリ・タグで検索し、サンプルをクリック／タップして再生する。
3. 「このレイヤーで試す」で**一時適用**。既存プロジェクトを汚さず中央プレビューに即時反映する。
4. 右側パネルで `適用範囲 / 開始位置 / 長さ / 速度またはイージング / 方向 / 移動距離 / 終了後の状態` を編集する。
5. 「採用」でプロジェクトへ反映。「取り消す」で試着前へ戻す。
6. 1レイヤーに複数アニメーションを設定し、タイムラインで開始・終了の重なりを確認できる。競合は警告する。
7. JSON 保存・再読み込み・Undo/Redo・プレビュー・MP4 レンダリングに同じ設定が引き継がれる。

#### 対象の違い（必須）
- **scene**：シーン全体に適用。
- **group / frame**：枠＋中の画像＋枠に紐づくテキストをまとまって動かす。ただしグループ構造に従い、別要素が勝手についてこないこと。
- **imageContent**：枠・マスクは固定したまま画像だけ移動／ズーム。枠の外はマスクで非表示。
- **text**：文字だけを動かす。タイプライターはテキスト以外への適用不可。
- **shape**：図形のみを動かす。

#### 退出演出の境界判定（最重要）
「左へ退出」「右へ退出」は単なる `translateX(-100%)` で済ませない。
- 移動前の要素の位置（X/Y）、サイズ（W/H）、回転後の外接矩形、親グループの変換、動画の論理解像度から、**完全に画面外へ出る終点**を算出する。余白（overshoot）も調整可能にする。
- `exitBoundary` を `canvas`（映像全体の外）/ `parentFrame`（親フレームから見えなくなる）で区別する。
- `imageContent + parentFrame` は枠の外に画像を出さず、クリップ領域内で画像が流れて消える。その際に空白が現れる仕様も許容するが、ループ表示・次素材への切替は別機能として扱う。
- `frame + canvas` は枠自体が完全に動画外へ退出する。元の配置・大きさを書き換えるのではなく、フレームごとの一時変換として計算する。
- プレビューの CSS 表示サイズ（例：横幅 800px）ではなく、1920×1080 など**動画の論理座標**で計算し、16:9／9:16／1:1や拡大縮小プレビューでも同じ結果にする。
- シークで途中に飛んでも正しい位置を表示し、途中再生・繰り返し・一時停止でも破綻しない。

#### 個別モーションデータの例（既存スキーマを調べて互換を取ること）
```json
{
  "id": "animation-001",
  "targetLayerId": "image-layer-03",
  "targetScope": "imageContent",
  "presetId": "A-005",
  "startFrame": 36,
  "durationFrames": 24,
  "params": {
    "direction": "left",
    "exitBoundary": "parentFrame",
    "easing": "easeIn",
    "overshootPx": 24,
    "fromCurrentPosition": true
  },
  "afterEnd": "holdEnd"
}
```
- `startFrame` はシーン内相対フレーム。全体フレームからはシーン開始位置で換算する。FPSを含む全体設定と矛盾しないこと。
- 速度倍率は開始・終了位置と整合すること。指定尺を変えずに速度倍率だけ増やすと到達位置が変わる等の曖昧な挙動にしない。
- `afterEnd` は少なくとも `holdEnd` / `restoreBase` / `hide` に対応する。
- JSON は保存・読み込み時にスキーマ検証し、旧バージョンの既存プロジェクトも読み込めるようマイグレーション対応する。

#### モーション合成のルール
- ベースの配置 (x/y/width/height/rotation) と、時間依存の変化量 (offsetX/Y, scale, rotationDelta, opacity, clipping) を分離する。
- `transform` を各モーションが上書きし合わないよう、評価関数が**合成した単一の描画状態**を返す。
- 移動＋ズーム＋フェードは同時適用可能にする。同一プロパティを競合して動かす組合せは、警告・優先順位・統合方針を定める。
- CSS transition / setTimeout / アニメーション開始時刻依存の副作用だけに頼らず、**指定フレームの状態を決定論的に計算する**。Remotionの `useCurrentFrame()`、`interpolate()`、`spring()` 等を既存構成に合わせて使用する。
- プレイヤーと最終出力で、できるだけ同じ描画コンポーネント・同じデータを使う。編集ハンドルや選択枠は最終動画へ含めない。

#### UI
- 現在の左側素材、中央ライブプレビュー、右側設定、下部タイムラインを維持。
- **中央：** レイヤー選択、試着再生、シーク、採用/取り消し。
- **右側：** 選択レイヤー名、適用先（枠全体/内部画像/文字など）、選択中のモーション、開始秒、尺、方向、距離、イージング、退出境界、終了時状態。数値は手入力／簡易スライダー双方で調整。
- **下部：** シーンタイムラインの選択コマを展開し、そのコマ内にレイヤーごとのアニメーションバーを表示する（初期は一覧と数値入力だけでも可、バーのドラッグ編集は次段階）。
- **左側：** 小サムネイルは必要時だけアニメーション再生し、一覧の60件を常時同時レンダリングしない。検索・タグ・対象種別フィルタを付ける。
- **日本語の指定補助：** 対象レイヤー選択中に「この画像を右から左へ画面外に退出」「枠は固定、画像だけ左へ流す」などを入力したら、まず構造化された設定案を表示し、承認後に適用する。最初の段階はルールベースの変換とテンプレートでよく、外部AI API連携は必須ではない。解析できない要求は既存の「Codex引き継ぎメモ」に紐づけて保存し、推測で適用しない。

### Phase 3｜拡張（Phase 2 の完了後）
- タイプライター＋スキャン＋発光などの重ね合わせを「演出レシピ」として保存。
- 位置・不透明度・拡大率の基本キーフレーム編集。
- MOTION ATLAS 60 から実装可能なものを順次移植し、`referenceOnly` / `previewOnly` / `renderReady` の状態を区別して表示。
- 複数選択レイヤーへの一括適用、キーフレーム・音同期等は本機能が安定した後に検討。

## 受け入れテスト（最低限）
1. 20秒 / 30fps の既存プロジェクトを開き、画像が入った円形フレームを選択。
2. A-005（左へ退出）を `frame` に試着すると、フレームと画像が一体で画面外へ退出する。採用前にキャンセルできる。
3. 同じレイヤーで `imageContent` + `parentFrame` に変更すると、枠は固定で画像だけ左へ移動し、枠外は表示されない。
4. 左・右・上・下の退出で、縦横比 16:9 と 9:16、プレビューの拡大縮小にかかわらず画面外へ完全に出る。
5. テキストを選択して A-021（タイプライター）を適用し、文字だけが順次表示される。画像レイヤーでは候補が無効になる。
6. 移動＋フェードを同時に適用しても transform / opacity の競合で演出が消えない。
7. 開始 1.2秒・尺 0.8秒へ変更すると、選択シーン内の正しい位置で再生する。シーク先を任意に変えても同じフレームは常に同じ見た目。
8. 保存→リロード、JSON出力→再読み込み、Undo/Redoで設定が保持／復元される。既存レイヤーの座標や素材は変更されない。
9. 動画の書き出し機能が既にある場合、同じ設定で出したMP4とプレビューの要所（開始/中間/終了）の見た目を比較し、一致を確認する。書き出し未実装なら、実装済みと偽らず残タスクを記載する。
10. 実装中の別機能（色変更・フレーム変更・画像配置・保存）について回帰テストを実施する。

## Codexへの作業ルール・報告形式
- 既存プロジェクトを作り直さず、現在のブランチ／ファイルを調査してから最小差分で実装する。
- いきなり24件を全部入れない。**先に A-005（左へ退出）を `frame` と `imageContent` で確実に動かし、次に左右上下移動→基本→文字→表示エフェクトへ広げる**。ただし最終成果物は24件の状態を正しく一覧管理できること。
- 各段階でブラウザ実操作を確認し、テスト結果を記録する。
- 既存データの破壊や「保存したのに再現されない」状態を避ける。未実装項目はUIで利用可能に見せない。
- 提出時に `①調査結果 ②追加ファイル・変更一覧 ③登録済み/適用可能/MP4対応数 ④テスト結果 ⑤未実装・既知の問題 ⑥次の推奨作業` を報告する。
