# AI PROMO STUDIO｜AI映像ディレクター（企画・構成強化）実装依頼書

> この文書は制作アプリの機能拡張案です。個別動画の制作基準ではありません。動画制作では [動画制作基準](動画制作基準.md) を参照し、アプリのAIディレクター機能を改修するときだけ本書のUI・データ設計を参照してください。

作成日：2026-11-14  
対象：現在ローカルで稼働中の AI PROMO STUDIO（既存のコマ・レイヤー・素材・モーション・タイムライン編集環境を維持）

## 0. この依頼の最優先目的

**「素材を並べて動かす動画」から、「デモの本当の価値を調べ、何をどう見せるかを企画した広告」へ進化させること。**

現状は、既存画面のはめ込みやボタン名の説明に偏り、商品の魅力・操作の気持ちよさ・印象に残る演出につながっていない。新しいモーションを増やすより先に、製品理解と企画構成の品質を上げる。

次の2つは必ず分けて扱う。

- **企画制作**：何を伝えるか、どの画面・操作を撮影するか、どんな演出で見せるかを決める。まずは絵コンテと簡易アニマティックまで。
- **本制作**：承認済み構成に沿って、素材撮影・レイヤー・モーション・音・MP4を制作する。

**企画承認前に大量の最終モーションやMP4を制作しない。**

## 1. 既存環境の調査（コード変更前）

1. プロジェクト構造と現行の制作フロー（依頼 → AI初稿 → コマ生成 → 編集 → 出力）を図解。
2. コマ・レイヤー・アニメーション・素材・JSON保存・Undo/Redo・Remotion Playerの既存データを調査。
3. デモURL／ローカルURL／プロジェクトフォルダ／画面録画／静止画など、調査に使用できる素材の入力手段を確認。
4. 既存のAIへの「制作依頼」「部分修正依頼」の処理を追い、企画フェーズをどこに挿入するか決定。
5. `docs/ai-director/00_current-state-audit.md`に調査結果を保存。既存データを破壊しない。

## 2. 企画工程を5段階に分離する

### Phase A｜製品・デモ実査（Product Audit）

**目的**：動画に採用できる「本当の操作」「本当の結果」「視聴者に伝えられる価値」を根拠つきで収集する。

- 入力：対象URL、ローカル起動済みサイト、ソースコード、説明資料、手元のキャプチャ、指定したターゲット／目的／動画尺。
- 対象にアクセス可能なら、Playwright等で主要画面を調査し、実際の操作を再現する。必要ならテストデータを使い、実サービスのデータは変更しない。
- 各操作について「画面・ボタン名／選択要素／操作前／ユーザー操作／操作後／見せられる変化／価値／スクリーンショット／根拠URLやコード位置／未確認事項」を記録。
- UI要素のターゲットは可能な範囲で`role+accessibleName`や`data-testid`のロケーターを保持。DOM上の位置は撮影時に再計測する。スクリーンショットしかない場合は手動の領域指定を許可。
- ログインが必要、操作が未実装、動作が確認できない場合は`unverified`とする。「実際に動いた」と偽装しない。
- サービスの機能・導入効果・所要時間・数値・AI処理などは根拠なしに断定しない。
- ユーザーには「撮影して良い操作」「重要なポイント」「未確認」を承認できる一覧を提供。

成果物：`product_audit.json`、`docs/ai-director/01_product-audit.md`、証拠画像／録画への参照。

### Phase B｜価値とメッセージの選定（Message Strategy）

**目的**：機能一覧ではなく、20秒で記憶してほしい「主張」を決める。

確認する項目：ターゲット、困りごと、約束する価値、その根拠となる実演、ブランドの印象、CTA。

- 候補から「この動画の主張はひとつ」を選ぶ。必要ならサブメッセージは1〜2件。
- 画面にあるボタン名を読み上げるだけの構成は避ける。
- **機能を見せる場面は、必ず「操作 → 目に見える変化 → それが伝える価値」の3要素**で考える。
- 機能が多い場合、全部紹介しない。価値を代表する操作を1〜2つ選ぶ。
- ブランド広告型では機能説明を短くし、感情／印象／製品の世界観を優先してよい。

成果物：`creative_brief.json`、`docs/ai-director/02_creative-brief.md`。

### Phase C｜3案の映像コンセプト（Creative Directions）

毎回、見せ方が実際に違う3案を生成する。タイトルだけ差し替えた案は禁止。

- **A｜操作実演型**：ボタンや操作、結果を見せる。視認性優先。ズーム／スポットライト／カーソル移動／処理前後の比較。
- **B｜ブランド印象型**：説明を絞り、文字・色・光・テンポを利用。操作は魅せ場だけを切り出す。
- **C｜課題→変化のストーリー型**：困りごとを短く提示し、操作と結果を通して解消のイメージを作る。

各案に必須の情報：

- 企画の一言、ターゲット、視聴後に残る印象、メインメッセージ
- 動画尺（20／30／40秒など）と各シーンの秒数
- 採用する実際のデモ操作・証拠素材ID
- 画面構成、カメラ表現、文字量、配色、緩急、BGM・効果音
- 見どころ／懸念／未確認事項／必要な追加素材
- 5つの評価基準（理解度、印象、独自性、証拠の確かさ、実装可能性）。数値と理由を表示し、ユーザーが編集可能にする。

**ユーザー承認ゲート**：案を採用・組み合わせ・再提案できる。承認するまで本制作は始めない。

成果物：`creative_directions.json`、`docs/ai-director/03_concepts.md`。

### Phase D｜秒単位の絵コンテ＋アニマティック（Storyboard & Animatic）

承認した案について、絵コンテを1シーンずつ展開する。各シーンに以下を持つ。

| 項目 | 例 |
|---|---|
| 目的 | 「ボタンを押すだけで結果に進める」ことを見せる |
| 実際の画面 | 受入検査デモの対象画面 `capture-02` |
| 実演する行動 | `照合開始`ボタンにカーソルを移動してクリック（実在・実動作の確認必須） |
| カメラ | 画面全体→ボタン周辺への寄り→結果部分への再フレーミング |
| 視線誘導 | スポットライト、周辺暗転、UIハイライト、短いライン演出 |
| 文字 | 「確認を、もっとわかりやすく」など短いコピーを1つ |
| 時間 | 3.0〜7.0秒、登場0.4秒、クリック0.6秒、結果2.1秒、余韻0.9秒 |
| 音 | クリックSE、結果が出る瞬間のアクセント |
| 根拠 | 画面キャプチャ／操作ログID |
| 具体的実装 | `sceneId`, `assetId`, `actionId`, `targetLocator`, `motionIds` |

- 各コマの静止サムネイル、重要フレームを表示。可能なら低負荷の「簡易アニマティック（仮動画）」をブラウザ再生。
- タイムラインに**機能実演トラック／カメラトラック／視線誘導トラック／コピー／BGM・SE**を分ける。既存の編集トラックへ転送できる形にする。
- ユーザーが「この操作をもっと大きく」「5秒目は説明を削る」「UIの操作は後半に寄せる」と自然言語で**シーン単位に編集**できる。
- 尺を変更するときは現状の総尺を維持するのか、全体を延長するのかを確認。変更しないシーンを勝手に編集しない。

成果物：`storyboard.json`、`capture_plan.json`、`docs/ai-director/04_storyboard.md`、簡易プレビュー。

### Phase E｜本制作への引き継ぎ（Production Handoff）

- 承認済み構成だけを、現在のAI PROMO STUDIOのコマ、素材、レイヤー、モーション、保存JSONに変換。
- 自動化できない動きは「未実装・要Codex作業」と表示。黙って静止素材へ置換しない。
- 動画プレビューとMP4出力が同じシーンデータを用いるようにする。
- 企画・手動編集・最終レンダリングを分離。必要ないMP4生成は行わない。
- 既存の「編集状態引き継ぎ」「AI部分修正」機能に接続し、確定済みシーンを保護。

## 3. 新設するUI：企画・構成タブ

既存の編集画面を消さない。プロジェクトの上位タブに`企画・構成`を追加し、必要なときは既存の`編集`画面へ移る。

`企画・構成`の推奨表示順：

1. **製品調査**：画面一覧、操作一覧、根拠画像、確認済み／未確認の区別。
2. **何を伝える？**：ターゲット、課題、価値、メインメッセージ、CTA。
3. **3つの企画案**：横並びカードでコンセプト・シーン構成・見どころ・評価を比較。再提案・選択・組合せ。
4. **絵コンテ**：各コマの「絵、秒数、実際の操作、演出、文字、根拠」を編集。自然言語の指示メモを紐付け。
5. **仮プレビュー**：本MP4を作らないアニマティック。問題を見つけて修正。
6. **企画承認**：「この構成で編集画面へ反映」を押すと、承認した内容だけ転送。巻き戻し可能なチェックポイントを保存。

操作UIは現在のアコーディオン方針に合わせ、全設定を開きっぱなしにしない。

## 4. 動画の演出パターン（具体的な登録候補）

汎用モーションの組み合わせではなく「実際の操作の価値を伝えるための見せ方」をレシピとして登録。

| レシピID | 演出名 | 画面で何をするか | 向く用途 |
|---|---|---|---|
| D-01 | UIフォーカス | 全画面→対象ボタンへ寄る→周囲をやや暗くする | 重要ボタン |
| D-02 | 操作→結果 | カーソル移動→クリック→実際の変化を撮影→結果へ寄る | 機能実演 |
| D-03 | Before / After | 同条件の画面を左右比較／ワイプで切り替え | 改善イメージ |
| D-04 | UI分解・再構築 | 機能の構成要素を一時的に分離して関係性を見せる | 複数機能の整理 |
| D-05 | 結果を主役に | 操作より結果画面を大きく表示、重要部分を強調 | 価値訴求 |
| D-06 | 連続操作の圧縮 | 実際の複数操作から要所だけをテンポ良く抜粋 | 操作の全体像 |
| D-07 | マスクで抽出 | UIの一領域だけ円形・角丸で抽出して背景へ重ねる | ブランド＋機能 |
| D-08 | カメラリレー | 操作位置→処理結果→次の判断位置へ視線をつなぐ | 流れの説明 |
| D-09 | 実画面×コピー | 画面の余白に短い主張を置き、操作を圧迫しない | 説明を抑える広告 |
| D-10 | 緩急インパクト | 直前に静止・減速→クリックで急展開→余韻 | 迫力・印象 |

これらは**映像ディレクション用のレシピ**であり、MOTION ATLASの汎用的な動き（M-001等）とは別IDで管理し、実装時に対応づける。

## 6. 検証用20秒ストーリーボード例（実在デモを見て再設計すること）

*以下は企画の形式を示す仮例であり、対象デモの機能・ボタン名・結果を確認した事実ではない。*

| 時間 | 見せたいこと | 映像表現 | 実際に必要な素材 |
|---|---|---|---|
| 0–3秒 | 課題・期待感 | 静かな画面＋短いコピー、徐々に寄る | タイトル／製品素材 |
| 3–6秒 | ひとつの主要操作 | 実画面を拡大→対象ボタンをハイライト→クリック | 操作前スクショ／操作ログ |
| 6–11秒 | 押すと何が変わるか | 画面録画を使い結果へフォーカス | 操作結果の録画／表示内容 |
| 11–16秒 | 価値の証拠 | 主要結果を抽出、短いコピーを重ねる | 強調対象のUI領域 |
| 16–20秒 | ブランド・次の行動 | 見せ場からロゴへ移行、CTA | 正式ロゴ／URL |

**動画の主役は「ボタン」ではなく、その操作によって何が変わるか。**

## 7. 品質ゲート（必須）

**調査ゲート**：最低1つの実動作確認、根拠画像、未確認項目の一覧。実動作不可なら明示して、手動素材で進める。  
**企画ゲート**：メインメッセージ1件、実演ポイント1件以上、異なる3案、ユーザーによる採否。  
**絵コンテゲート**：各シーンに目的／表示内容／カメラ／文字／時間／素材の出所がある。  
**実装ゲート**：承認されていない企画を勝手に本制作しない。既存編集の保存・取り消し・レイヤー・素材機能が維持される。  
**表示ゲート**：機能説明のテキストをただ並べるだけのシーンがない。主要な機能実演では必ず操作と画面の変化を確認できる。

## 8. Codexの実装順序

1. まず現状監査・変更計画を保存する。
2. 製品調査結果のデータ定義と手動登録画面を作る（自動スクレイピングは後でもよい）。
3. Creative Brief、異なる企画3案の生成・比較・保存UIを作る。
4. 絵コンテ画面、自然言語メモ、承認と再編集を実装。
5. 既存コマ・レイヤーへ変換する機能とチェックポイントを実装。
6. Playwrightによる実操作キャプチャと演出レシピを段階的に接続。
7. 仮プレビューと本プレビューの一致・MP4テストを行う。

最初から完全自動のCM生成を実装しようとしないこと。**調査・企画・絵コンテをユーザーが吟味できる環境を優先**する。

## 9. 完了報告に含めること

- 現行システムの調査結果と追加・変更したファイル
- 動作する企画・構成タブのスクリーンショット
- 実際の1デモについての調査結果・3案・承認済み絵コンテ
- 何を自動化でき、何を人が確認する必要があるか
- 未実装項目と問題点、ブラウザでのテスト結果
- 既存編集・保存・Undo/Redo・MP4に退行がないことの確認

## すぐにCodexへ渡す短縮依頼

このMD全体を読み、既存のAI PROMO STUDIOに「AI映像ディレクター（企画・構成）」工程を追加してください。現状はめ込みとテキスト説明に偏るため、デモの実査→動画の主張選定→異なる企画3案→秒単位の絵コンテ・仮プレビュー→ユーザー承認→既存エディタへの変換の順に変更したいです。**最初は本動画の生成を急がず、何をどう見せるかを徹底して考える仕組みの実装を優先**してください。初めに既存コードを監査し、互換性のある実装計画を文書化してから段階的に実装・ブラウザ検証してください。未確認の機能は事実として描写しないでください。
