# 完成動画とHTMLの保存ルール

## 保存先

完成品はルートの **動画ライブラリ/** にまとめる。最初に [動画一覧](../動画ライブラリ/index.html) を開き、対象・雰囲気・尺・言語・演出名で検索する。制作中の素材・編集データは `promo-studio/jobs/<job>/` に保持する。

「1作品を1フォルダ」にし、その中にMP4・HTML・ポスター・作品情報・検査結果を置く。HTMLはMP4とポスターを同じフォルダから参照するため、作品フォルダ単体を別の場所へコピーしても再生できる。編集データは作品情報から元の案件を特定する。

## 命名規則

```text
動画フォルダ_<対象>_<雰囲気><秒数>秒_<言語>_<画角>_<内容・演出>_<制作日YYYYMMDD>_v<版番号2桁>
```

例：

```text
動画ライブラリ/
  index.html
  作品一覧.json
  動画フォルダ_トーナメント_迫力22秒_英語_横型_9種転換_20261112_v01/
    トーナメント_迫力22秒_英語_横型_9種転換_20261112_v01.mp4
    トーナメント_迫力22秒_英語_横型_9種転換_20261112_v01.html
    トーナメント_迫力22秒_英語_横型_9種転換_20261112_v01_ポスター.png
    作品情報.json
    検査結果.json
    この動画について.txt
```

尺は依頼の正確な秒数を使う。今回の迫力版は22秒であり、30秒という名前にはしない。画角は横型・縦型・正方形を解像度から判定。ファイル名に使えない文字、空欄、長すぎる値は出力前に拒否する。

## 制作時の設定

新しい案件には `delivery.json` を用意する。既存のdelivery.jsonを参考にする。

```json
{
  "subject": "トーナメント",
  "tone": "迫力",
  "language": "日本語",
  "variant": "ロック",
  "description": "実際に何が見える動画かを一文で記載",
  "date": "20261112",
  "version": 1
}
```

`render.mjs` は設定を検査して書き出す。`qa.cjs` が全編検査に合格すると、検査したMP4のSHA-256を記録し、完成品をライブラリへ自動集約する。検査済みファイルと現在のMP4が違えば集約しない。

```powershell
# promo-studioで実行
node scripts/render.mjs jobs/<job>
node scripts/qa.cjs jobs/<job>
# 検査済みの既存案件を再集約・一覧更新
npm run library
```

## 版の扱い

- 同じ案件・版・内容の再集約は可能。
- 同じフォルダ名で別動画や別HTMLに上書きする操作は拒否する。修正時はversionを2、3…と上げる。
- 対象・言語・内容の違う作品は名称で区別する。旧版は残し、一覧には版番号も表示する。
- 削除・移動は自動で行わない。ライブラリは完成品の集約先、jobsは編集・検査の正本。
- 過去のMP4・共有ZIP・HTMLへのリンクを壊さないため、既存jobs内の成果物は保持する。

## 今回の整備範囲

既存4作品に加え、DDの高級感・信頼感20秒版も同じルールで集約済み。現在5作品。30秒への延長は行っていない。22秒版・20秒版を実際の尺で命名する。
