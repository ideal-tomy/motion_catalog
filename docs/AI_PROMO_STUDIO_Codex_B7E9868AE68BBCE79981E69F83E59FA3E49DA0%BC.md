# AI PROMO STUDIO｜編集状態・変更希望の蓄積とCodex引き継ぎ機能：実装依頼

## 目的

既存のローカル AI PROMO STUDIO を拡張してください。目標は「AIに動画を丸投げする」のではなく、**ブラウザで画面構成、フレーム、画像、テキスト、色、尺、動きを試す → よい状態を保存する → ブラウザで実現できない希望だけ日本語で書きためる → その時点の確定状態と未実装の要望を正確に報告してCodexへ引き継ぐ → 必要な実装・出力だけ依頼する**というワークフローです。

「うまいプロンプトを自動生成すること」が目的ではありません。**現在のプロジェクトを正確に説明する、再現性のある状態報告書（handoff）を作ること**が目的です。

## 最重要ルール

1. **最初に既存コード・データ形式・保存方法・Undo/Redo・プレビュー・モーション・素材管理・書き出し状況を調査し、短い現状レポートを出してください。** 既存の動作ができている機能は維持してください。新しい動画編集アプリを作り直さないでください。
2. **実装済みの編集結果、ユーザーがまだ希望している変更、Codexで実装が必要な変更を混同しないでください。** すでに画面に反映済みの内容を再実装するようAIに指示しないこと。
3. **保存されたプロジェクトの状態が唯一の正本**。要約文とJSONで食い違いを生じさせないこと。報告書は保存データから生成し、ユーザーが書いたメモは別に保持すること。
4. AI修正を適用する際は**対象シーンID・レイヤーIDの範囲を限定**し、未指定のコマ・手動で確定済みの設定を変更しないこと。必要なら適用前に差分を示し、承認・取り消しできること。
5. **ローカルファースト**で実装。認証、クラウドDB、新しい外部AI API連携は現段階で必須にしないこと。既存技術・構成を優先すること。
6. 既存のMP4書き出しが未対応の演出は、「プレビュー上で確認済み」と「MP4出力で再現確認済み」を分けて記録すること。報告書に未確認の成功を記載しないこと。

## 1. 追加したい編集体験

既存の左側（構成・素材・動き・AI部分修正）、中央（ライブプレビュー）、右側（コマ・レイヤー設定）、下部（タイムライン）を維持してください。新たに折りたたみ式の **「修正メモ／引き継ぎ」パネル** またはタブを追加してください。

### 1-1. 編集しながら日本語の希望をためる

- コマ全体・フレーム・画像・テキスト・その他レイヤーのいずれかを選択した状態で「この対象への修正メモを追加」。
- 例：「この円形フレームは左から入って、0.6秒で止めたい」「画像だけゆっくり拡大したい」「このテキストをタイプライター表示にして、後から青いスキャンラインを重ねたい」。
- 全体を対象としたメモも追加可能。例：「全体は紺を基調にし、アクセントの水色は強調部分のみに使う」。
- メモの作成時に `projectId / sceneId / layerId（あれば） / 対象名 / 記入時刻 / コメント / 種別 / 状態` を保存する。あとで別のコマを選択しても対象がすり替わらないこと。
- 種別は「未実装の希望」「確認してほしい点」「書き出し時の注意」など。状態は「未対応／確認待ち／対応済み／保留」。
- 訂正、並び替え、削除、まとめて選択できること。実装が済んだメモは手動で対応済みにできること。
- 対象シーンやレイヤーが削除された場合、紐付けが切れたことを警告し、勝手に他の対象へ付け替えないこと。

### 1-2. 「この状態で保存」と履歴

- 現在の作品を「確定版」「作業中の案」などの名前付きチェックポイントとして保存できること。
- プロジェクト名、総尺、fps、コマ一覧、レイアウト、素材参照、全レイヤーの位置・サイズ・マスク・回転、文字、色、モーション設定・時間軸を保持すること。
- 手動で調整した変更を記録する。変更履歴の例：「シーン02／円形フレームの幅 30%→42%」「シーン03／タイトル色 #FFFFFF→#A9E5DF」「シーン03／尺 7秒→9秒」。
- 一時的に試して元に戻した内容は、最終的な引き継ぎの『確定変更』に含めないこと。
- 保存済みの比較基準（チェックポイント）と現在の状態を比較し、**最終的に残った差分**だけを表示する。報告書の基準バージョンも明示すること。
- 既存のUndo/Redo、プロジェクトの保存・復元と競合しないこと。ページ再読み込み後もチェックポイントとメモを復元できること。

### 1-3. 差分確認と引き継ぎ

パネルには次の3つを明確に分けて表示してください。

**A｜現在確定している内容**：総尺、構成、各シーンの時間、各レイヤーの素材・位置・色・モーションなど。Codexに「これは既存の確定状態なので変更しない」と伝えられるようにする。

**B｜基準チェックポイントからの確定差分**：手動変更した部分だけを対象・変更前・変更後で示す。構造化JSON差分と人間が読みやすい要約の両方を持つ。

**C｜まだ実現していない希望・要確認事項**：日本語メモを対象に紐付けて一覧化。実装要件と質問事項を区別する。

「引き継ぎ資料を作成」ボタンで、A/B/Cを統合した読みやすい日本語の報告書を生成する。プロンプト風の装飾は不要。**事実・差分・残作業・出力条件**が分かる文書にすること。

### 1-4. 引き継ぎの目的を選択

以下のモードを用意してください。

- **未実装の演出をCodexに依頼**：現在の状態を壊さず、選択された修正メモだけ実装を依頼するための資料。
- **現在の確定状態を動画に書き出す**：手動編集後の状態、使用素材、尺・音声・解像度・fps、プレビューと最終出力の一致確認項目をまとめる資料。
- **レビュー・調整相談**：現在の画面構成・演出と、ユーザーが気になっている点を整理する資料。

モードが違っても**同一のプロジェクトデータを参照**すること。ユーザーが編集した状態をAIが想像して書き直さないこと。

## 2. UIにほしい操作

- 右パネル：対象選択時に「修正メモを追加」ボタン。
- 左側または下部の「引き継ぎ」タブ：メモ一覧、対象ごとの絞り込み、確定差分、チェックポイント比較。
- 「保存して引き継ぐ」ボタン：保存→差分更新→引き継ぎプレビューを表示。
- 「引き継ぎ文をコピー」「MDを保存」「JSONを保存」「一式を保存」を提供。
- 引き継ぎプレビュー中もシーン・レイヤーへジャンプできること。
- レポートにはシーンID・レイヤーIDと日本語の表示名を併記すること。
- モーション図鑑や素材選択の操作を妨げず、既存のUI配置を大きく変えないこと。

## 3. 取り扱うデータ

既存のプロジェクトJSONを正本として維持し、互換性を崩さない形で以下のメタデータを足してください（実際のキー・配置は既存コードに合わせて調整してよい）。

- `checkpoints[]`: `id`, `label`, `createdAt`, `projectVersion`, `snapshot` または復元可能な参照。
- `editNotes[]`: `id`, `scope`, `sceneId`, `layerId`, `text`, `kind`, `status`, `createdAt`, `updatedAt`。
- `handoffRecords[]`: `id`, `baselineCheckpointId`, `targetCheckpointId`, `purpose`, `createdAt`, `selectedNoteIds`, `exportPaths`（存在する場合のみ）。
- `assetManifest[]`: `assetId`, `originalName`, `mediaType`, `storedPath / storageKey`, `licenseOrSource`（任意）。一時的な `blob:` URL を唯一の素材参照にしないこと。
- `renderCompatibility`: プレビュー確認状況とMP4再現確認状況を個別に表す項目（必要な場合）。

差分計算は安定したシーンIDとレイヤーIDを基準にし、配列順序が変わっただけで全項目変更と判定しないこと。数値の単位（秒、フレーム、%、pxなど）を明示すること。20・30・40秒など総尺の違いにも対応すること。

## 4. 引き継ぎ資料の出力内容

例：

```md
# AI PROMO STUDIO｜編集引き継ぎレポート

- プロジェクト：DD 素材付き編集サンプル
- 基準：Checkpoint v12
- 現在：Checkpoint v15（2026-11-13）
- 総尺：20秒／30fps
- 今回の目的：未実装の演出のみ実装

## 現在確定している状態
- シーン01：0–5秒、1画面、画像素材A、円形フレーム
- シーン02：5–10秒、2分割、画像素材B・C

## 基準からの確定変更
- シーン01／frame-a：直径を30%→42%に変更（手動編集済み）
- 全体配色：背景を#0C1727、アクセントを#6FD2C9に変更（手動編集済み）

## 未実装・Codexへ依頼したい内容
- シーン01／frame-a：左から0.6秒でスライドインし、停止後も内部画像のみ緩やかにズーム
- シーン02／title-b：タイプライター表示の後半にスキャン線を重ねる

## 変更禁止範囲
- 上記以外のシーン、レイヤー、素材、尺、確定済み配色は維持

## 出力・検証
- まず既存プロジェクトをバックアップし、変更案の差分を確認
- 実装後、ブラウザのプレビューで各シーンの動きを確認
- MP4出力への互換性は別途検証し、未対応は明記
```

これは形式例であり、実際の内容は**保存された状態とユーザーのメモからのみ生成**してください。不存在のID・演出・確認結果を捏造しないこと。

## 5. 実装順序

### Phase 0｜現状調査
- 既存プロジェクトのデータ構造、保存・Undo/Redo、素材の永続化、モーション設定、プレビュー、レンダリング経路を確認。
- 追加ファイルと改修箇所を提示。破壊的なデータ移行を避ける。

### Phase 1｜修正メモとチェックポイント
- コマ・レイヤーに紐付いた自然言語メモの追加・編集・削除・保存。
- 名前付きチェックポイントの作成と復元。ページ再読み込みで維持。

### Phase 2｜確定差分の可視化
- チェックポイント間の構造化差分を計算し、対象別にわかりやすく表示。
- 変更を戻した場合に差分が消えることを検証。

### Phase 3｜引き継ぎ文生成と書き出し
- 現在の状態・確定差分・未実装メモを統合し、目的別のMDを生成。
- コピー、MD/JSON出力、可能なら素材を含むZIP形式の一式出力。
- 機械可読データと自然言語レポートの整合性を確認。

### Phase 4｜必要に応じてAI接続
- まずはCodexへ手渡す資料で運用可能にする。
- AIによる直接修正は別フェーズとし、適用前の差分承認・対象限定・Undoを必須にする。

## 6. 動作確認・受け入れ条件

1. シーン01の円形フレームを移動・拡大して保存し、シーン02のテキストに日本語メモを追加できる。
2. シーン02の色を変更後に元に戻した場合、その色変更が「確定差分」に残らない。
3. 「シーン02のタイトルをタイプライター表示」メモを追加すると、**シーン02の対象レイヤーID付き**で引き継ぎ資料に出る。
4. 手動で反映済みの変更は「確定済み」として報告し、「まだ実装してほしいこと」と混ざらない。
5. 保存・再読み込み・プロジェクト切替後も、正しいチェックポイントとメモを保持する。別プロジェクトへの混入はない。
6. 20秒・30秒・40秒の作品で総尺、シーン開始位置、秒数が一致する。
7. 画像・動画などの素材参照が引き継がれ、復元不可な素材があれば警告する。
8. JSON出力、既存のモーション図鑑、フレーム操作、素材アップロード、ライブプレビュー、Undo/Redoを壊さない。
9. 「未実装の演出依頼」と「そのまま書き出し」の2モードで、同一プロジェクトから**異なる目的の正確な報告書**を生成できる。
10. 変更したファイル、テスト結果、未対応箇所を日本語の短いレポートで提出する。

## 7. 作業指示

まずPhase 0の調査を行い、既存設計に沿った実装計画を示してください。その後、**Phase 1からPhase 3までを段階的に実装・実機確認**してください。既存機能の不具合調査や修正が進行中なら競合を避けてください。新しいAI APIやクラウドを追加するより、**ユーザーの編集状態を正確に保存し、実装を依頼したい内容をまとめる能力**を優先してください。
