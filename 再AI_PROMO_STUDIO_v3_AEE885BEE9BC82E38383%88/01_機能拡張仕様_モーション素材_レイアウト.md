# AI PROMO STUDIO｜次期機能拡張仕様 v3

作成日：2026-11-13

## この拡張の目的

ローカルで稼働中の AI PROMO STUDIO を**作り直さず**、既存の画面（左：機能タブ、中央：ライブプレビュー、右：選択コマ設定、下：タイムライン）を維持したまま、次の順番で使えるツールにする。

1. MOTION ATLAS 60 の各動きを**見て探せる**ようにする。
2. アップロード画像・動画を**サムネイルで識別**できるようにする。
3. シーンごとの画面構成を**テンプレートから選び、自由編集**できるようにする。
4. 選んだ画面やモーションを試着・取り消し・保存できるようにする。
5. 保存した構成を基に、最終段階で MP4 / 共有用HTMLへ書き出せるようにする。

本番環境や既存デモを触らず、現在の制作プロジェクトを保持すること。

## 既存環境の観察事項（ユーザー提供スクリーンショットに基づく）

- 左に「構成／素材／動き／AI部分修正」、中央にライブプレビュー、右に選択コマ編集、下にタイムラインがある。
- 「動き」の検索欄はあるが、名前が中心で直感的に動きを比較できない。
- モーション図鑑画面は60件のカードを並べるが、カードのサムネイルだけでは実際の動きを十分に理解できない。
- 一部モーションは「見本のみ・挿入不可」と表示されている。これは状態として正しく維持する必要がある。
- 「素材」で画像をアップロードできるが、ファイル名中心で、どの写真か即座に識別できない。
- コマの画面構成は4分割などがあるが、自由なサイズ・形状・重ね順の編集には未対応と見える。
- **注意：実際のアプリのソースコードには本資料作成時点でアクセスできていない。** 以下は既存実装の確認後に適用する仕様。スクリーンショットに写っている動作を推測で「実装済み」と認定しないこと。

## Phase 0｜既存プロジェクトの監査・保護

- package.json、コンポーネント構成、Project/Scene/Layer のデータ構造、保存/再読込、Undo/Redo、プレビュー、MP4 出力経路を確認する。
- 作業前に git status / branch / log を確認し、未コミットの変更や制作物を消さない。
- `docs/EXTENSION_V3_AUDIT.md` に現状機能、再利用可能なコード、未対応を記録する。
- MOTION ATLAS 60 の `index.html` または相当する資産をローカルで特定する。なければ「ソース未取得」と明記し、見本の動きを想像で実装しない。
- 既存の sceneId、layerId、motionId（M-001〜M-060）は変更しない。必要なら互換アダプターとマイグレーションを用意する。

## Phase 1A｜モーション図鑑を「実際に動くカタログ」にする

### UI

- 左の「動き」タブに「モーションを探す」を置き、カード一覧は横幅をとれる**モーダルまたは別パネル**で開く（左の細い欄に60件を長く並べない）。
- 各カードに ID、名称、カテゴリ、感情タグ、**動きが分かるプレビュー画像**、実装状態を表示。
- カテゴリ：文字 / UI / カメラ / 場面転換 / エフェクト / 音同期。
- タグ：迫力 / 高級感 / 信頼感 / 癒し / スピード / ゆっくり 等。複数タグを併用可能。
- カードクリック/タップで詳細パネルを開き、**実際の2秒前後の動きを再生**。再生/停止/再再生/速度変更ができる。
- 詳細パネルに推奨テキスト量・文字色・推奨配置・適合するシーン・使いどころを表示。
- 代表例：「M-008 スキャニングUI」を選ぶと、その名称から想像する動きではなく、元の図鑑と同種の走査演出が再生される。
- 適用可能なものだけに「選択レイヤーに試着」を表示。試着中は未確定、採用/キャンセルを明示する。

### 技術

- 元の MOTION ATLAS 60 は単一の Canvas 2D プレイヤーと `MOTIONS` 配列、`draw()` / `scene()` / `drawExtended()` 系の描画機構を用いている。これを読み取り専用の参照元として、**ID・進捗・Canvas コンテキストを指定して1種類を描ける再利用モジュール**へ切り出すことを優先して調査する。
- 60個の iframe または 60個の常時稼働 Canvas を使わない。
- 一覧はポスター（静止画像）を基本とし、ユーザーが選択した**1件だけ**動かす。PCではhover再生も可能だが任意。タッチ端末はtapで再生。
- 再生中でないプレビューや画面外のプレビューではアニメーションを停止する。IntersectionObserver の利用を検討。
- **「図鑑で視聴可能」と「選択コマに挿入可能」と「MP4出力可能」を別の状態として管理**する。現在4件挿入可能なら、残りの56件はプレビューのみでも問題ない。
- アニメーションがCSSの自走、Date.now()、不定な乱数に依存したままの実装は本番のMP4出力に混ぜない。出力対応版はフレームに対して決定的な描画にする。

### 受け入れ条件

- M-001〜M-060を検索可能。任意の5件を切り替えると**それぞれ異なる本来の動き**が再生できる。
- 未対応素材は「試着・出力不可」と分かりやすく表示される。
- 図鑑を閉じるとプレビュー用処理が停止し、ライブプレビューの再生に影響しない。
- 既存のコマ・タイムライン・保存内容は変更されない。

## Phase 1B｜アップロード素材のビジュアルライブラリ

### UI

- ファイル名だけのリストから、正方形または横長の**サムネイル付きカード**へ。
- 画像：縮小画像、ファイル名、寸法、種類。クリックで拡大。
- 動画：ポスター画像、再生時間、寸法、再生ボタン。クリックで再生。
- 選択素材を「選択コマの領域に配置」「レイヤーとして追加」「背景に設定」できる。
- 配置後にフィット方法（cover / contain）、切り抜き位置、回転、透明度、重ね順を調整できる。
- アップロード直後だけでなく、**保存→ページ再読み込み後もサムネイルと配置状態が復元**される。

### 永続化・速度

- Blob URL は一時表示用であり、プロジェクトの参照元としてそのまま保存しない。
- 既存のローカル保存方式を確認し、永続的な assetId と実ファイルの対応を保持する。ローカルサーバー側の assets ディレクトリ、IndexedDB 等から、既存構成に適した方法を選択。
- JSONには画像/動画のBase64本体を埋め込まず、assetId・メタデータ・参照先のみ保存。
- サムネイルは別サイズで用意。原寸動画や高解像度画像を全件同時デコードしない。
- 非対応形式・破損・巨大ファイルには説明を表示。オブジェクトURLやデコーダー資源を後片付けする。

### 受け入れ条件

- JPG、PNG、WebP を2点アップロードしたら、**両方の実画像が見え**、正しい方を選んで4分割の任意1セルへ配置できる。
- 保存してブラウザを再起動しても、サムネイルと配置が復元する。
- 追加・削除・Undoが既存の操作系と矛盾しない。

## Phase 2A｜画面構成テンプレート（最優先の制作機能）

初期テンプレート12種。各項目は**図解サムネイル**と名前で表示し、選択するとコマだけに試着できること。

| ID | 名前 | 内容 |
|---|---|---|
| L-01 | 全画面 | 1枚の映像を全面表示 |
| L-02 | 左右均等 | 左右50:50 |
| L-03 | 左右非対称 | 主役70:補助30 |
| L-04 | 上下分割 | 上下50:50 |
| L-05 | 主役＋縦2小窓 | 左大・右上下小 |
| L-06 | 4分割 | 均等2×2 |
| L-07 | 主役＋3小窓 | 1面を大きく、3面を小さく |
| L-08 | ピクチャーインピクチャー | 全画面＋重ねる小窓 |
| L-09 | 円形フレーム | 背景の上に円形に切り抜いた素材 |
| L-10 | ひし形フレーム | ひし形に切り抜いた素材と背景 |
| L-11 | 斜め分割 | 斜め境界で2領域 |
| L-12 | フリーコラージュ | 大小の四角と円が重なる非対称配置 |

**テンプレートは最初からレイヤー編集できる初期値**とし、採用後も位置やサイズを自由に変更できる。

### 非破壊の切替

- 既存の4分割から「円形」に変更した時、使われなくなる素材は**削除せず保留トレイに残す**。
- 変更前後プレビューと「採用／キャンセル」を置く。
- レイアウト変更は**現在のsceneIdだけ**に作用。他のシーンと全体尺を勝手に変えない。
- タイトルの重なりなどの警告を出しても、勝手な修正やデザインの上書きをしない。

## Phase 2B｜PowerPointに近い自由配置編集

### 操作

- 編集モード時は中央プレビューの上に選択枠・変形ハンドル・ガイドを重ねる。動画再生モードでは非表示。
- 追加パレット：長方形 / 角丸四角 / 円・楕円 / ひし形 / テキスト / 画像 / 動画。
- クリックで選択、ドラッグで移動、四隅で拡縮、回転ハンドルで回転、Deleteで削除（確認/Undo対応）。
- 前面へ / 背面へ、複製、中央揃え、等間隔、スナップ、縦横比固定、ロック、非表示。
- 円・ひし形のフレームの**内部に画像・動画を切り抜いて表示**できる（単に丸い図形を重ねるだけではない）。
- 1つの形状を選んでから「このフレームに素材を入れる」操作ができる。
- 文字は独立したレイヤーとして内容・フォント・色・位置・タイミングを編集できる。
- モーションの適用対象はシーン全体か、特定のレイヤーか、マスク内の素材かを明確にする。

### 描画設計

- 画面サイズは1920×1080などの**論理座標**で固定し、ブラウザ内は縮尺表示。位置保存は正規化座標（例 x/y/w/h = 0..1）または同等の一貫した論理座標にする。
- 実データ `scene.layers[]` に shape、mask、transform、zIndex、assetId、text、motionStack を保存。
- SVG の clipPath またはCSSクリップ/マスクを用いて、自由配置の円・ひし形切り抜きを作る。端末やMP4レンダリングの互換はテストする。
- エディタのドラッグ・回転・リサイズ操作だけに `react-moveable` 等のライブラリを利用できる。**編集ハンドルは動画出力に映さない**。
- プレビューとMP4では、可能な限り同じ scene JSON・同じ描画コンポーネントを使う。独立したCanvas図鑑から流用した動きは、Remotion出力との互換を個別に検証する。
- 編集操作と動画の再生は別状態として管理する。ドラッグ操作中は一時停止可、完了後に再生で確認できる。

### 使用イメージ

1. 2コマ目の「4分割」を選択。
2. L-07「主役＋3小窓」を試着。
3. 左の大きな枠を少し拡大、右上の小枠を円形に変更。
4. 円内にアップロードした画像を配置してトリミング。
5. 背景に文字レイヤーを追加、フォント色を変更。
6. 選択円の出現モーションを適用→大きなプレビューで確認。
7. 問題なければ採用・保存。変更は2コマ目だけに反映。

## データ契約例（概念。既存スキーマに合わせてアダプターを作ること）

```json
{
  "sceneId": "scene-02",
  "durationFrames": 120,
  "layoutPresetId": "L-09",
  "layers": [
    {
      "layerId": "layer-image-01",
      "type": "media",
      "assetId": "asset-001",
      "bounds": {"x": 0.15, "y": 0.12, "width": 0.55, "height": 0.72},
      "rotationDeg": 0,
      "mask": {"type": "ellipse"},
      "fit": "cover",
      "opacity": 1,
      "zIndex": 2,
      "motionStack": [ {"motionId": "M-003", "startFrame": 0, "durationFrames": 30} ]
    },
    {
      "layerId": "layer-title-01",
      "type": "text",
      "text": "ひと目で分かる。",
      "bounds": {"x": 0.58, "y": 0.35, "width": 0.35, "height": 0.2},
      "fontColor": "#FFFFFF",
      "zIndex": 5
    }
  ]
}
```

- `bounds` は表示領域に対する割合。形状と媒体は別に管理。
- `sceneId` と `layerId` の維持、旧データの読み込み、Undo/Redo、保存→再読込を優先。
- 上記の M-003 は**データ構造例**であり、現在の環境で出力実装済みと断定するものではない。

## 重くしないための原則

- 60モーションの一覧で全件を動かし続けない。通常はサムネイルだけ、再生するのは選択1件。
- アップロード画像は一覧用縮小画像を別に作り、原寸素材を60枚同時に展開しない。
- 動画は代表フレームを表示し、再生中の動画デコード数を制御する。
- 中央プレビューは1本を集中再生。複数のプレイヤーや編集中の不要な副描画を減らす。
- 編集ハンドル・ガイドは編集時だけ表示し、再生時と出力時には描かない。
- 3Dシェーダーや重いエフェクトを後回しにし、まずDOM/SVGの自由配置・マスク・基本トランジションを完成させる。
- 遅くなる原因を実測（操作遅延/フレーム落ち/メモリ使用）してから最適化する。静止画中心の数個のレイヤーのために最初から大規模な描画エンジンを新設しない。
- MP4の最終出力は確定後。編集中の変更ごとにMP4を書き出さない。

## 推奨の実装順序

1. Audit + 保護 + ソース取り込み経路整理。
2. モーション動的プレビュー／画像サムネイル：**先にユーザーの見分けにくさを解消**。
3. レイアウト12種／サムネイル一覧／試着／非破壊適用。
4. 自由配置（四角・円・ひし形・テキスト・素材）とドラッグ/サイズ/重ね順。
5. 素材クリッピング・文字モーション・複合モーション。
6. 保存/再読込/Undo/Redo / AIへの部分修正パッチ / 書き出し整合性テスト。

## 完了検証

- 図鑑内でM-001、M-008、M-020など**異なる3種類の動き**が実際に再生できる。
- 画像2枚のサムネイルでどちらの画像か直ちに判別できる。再読み込み後も残る。
- L-01〜L-12のレイアウトサムネイルを見て違いが理解でき、クリックで選択コマに試着できる。
- 4分割→円形＋文字＋小窓に変更し、ドラッグで位置・大きさを変え、保存→再読み込みできる。
- 既存の20秒構成の他コマ、タイムライン、編集履歴、素材参照が壊れない。
- 編集ハンドルが完成動画や共有用HTMLに表示されない。
- ブラウザのドラッグ操作・プレビュー再生が通常の制作に支障なく使えることを実機で検証する。
