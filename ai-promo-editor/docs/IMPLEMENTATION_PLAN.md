# 設計セットの監査と実装範囲

今回の依頼は動画の追加制作ではなく、独立したローカル編集アプリのStep 1・2。`promo-studio/` や対象デモのソース・本番環境には変更を加えない。MP4出力・有料AI自動呼び出しは今回の段階に含めない。

## 設計上の差分と決定

- モックJSONは正式schemaと別形式。正式example-project.jsonを初期データとする。
- サンプルは素材0点、split2/grid4だがセルの割当データがschemaにない。`layer.style.cellIndex` を追加情報として使う。未割当セルを明示し、レイアウト変更でレイヤーを削除しない。
- 自由配置のマスクも `layer.style.mask`、動画トリムと再生速度はstyle内で保持する。厳格schemaは変更せず、既存のstyle/params/meta拡張枠を利用する。
- スキャンの重ね合わせや一部の初期モーションはStep 3要件。編集コア検証用に4件だけフレーム駆動アダプターを実装し、MP4検証前なのでimplementedと表示する。旧制作環境でのverified状態を新アダプターに流用しない。
- 手動保護は必須なので、局所patchのdry-run・差分承認・revision・ロック・手動変更パスの拒否を編集コアと同時に実装する。AI APIは呼び出さずファイルで候補を受け取る。
- 総尺はdurationFramesの合計。尺変更とアニメーション速度は独立。固定尺の再配分は候補→承認でのみ適用。
- 保存はlocalhost API、JSON Schema＋意味検査、revision競合検出、履歴保存、一時ファイル→rename。素材はプロジェクト内相対パスのみ。
